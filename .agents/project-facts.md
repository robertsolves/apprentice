# Project facts for the generic commands and skills

The generic commands in `.agents/commands/` read this file for what they need to know about apprentice. `AGENTS.md` is the agent guide; this file only points into it and the docs it names.

- **Checks and tests** after a change: `swift build`, then `.build/debug/apprentice selftest` (there is no XCTest target and no linter). `apprentice commit "what and why"` rebuilds, restarts and commits one change. A fix to a pure part (TOML, args, pace, wire, routing, `diff`, the gate, budgets, policies, allowlists, flows, notes) gets a check in `Sources/apprentice/SelfTest.swift`.
- **Records**: open bugs `BUGS.md` (field-report format, `### F<n> · summary — date`, see "BUGS.md and TODO.md" in `AGENTS.md`), deferred work `TODO.md`. There is no changelog: the commit message is the record.
- **Audit records**: none per topic; every sweep files what it doesn't fix in `BUGS.md` (bugs) or `TODO.md` (everything else), and a re-run re-checks those entries first.
- **Product brief** (`/audit-product`, `/interview-code`): what apprentice is and who it is for is "What this is" in `AGENTS.md`; the design is `SPEC.md` (where it disagrees with the code, the code wins, per "Architecture" in `AGENTS.md`); the user-facing pitch is `README.md` and `site/index.html`; the feature list is `FEATURES.md`; launch status is `production_readiness.md`. Out of scope by design: bulk outreach, mass following, scraping at volume, several accounts on one site, local models.
- **Core docs** (`/update-docs`, `/interview-docs`, `/improve-markdowns`): `AGENTS.md` must match the code; `agent/SKILL.md` and `agent/AGENTS.md` must match each other and the CLI and stay under about 600 tokens each; exit codes must agree across `SPEC.md`, `usage()` in `Sources/apprentice/main.swift` and `agent/*.md`; `notes/README.md` defines the notes format. Text read from a screen is untrusted and never goes into notes or docs.
- **Search helpers**: `rg` over `Sources/apprentice/` (one target, no packages); `apprentice grow` and `apprentice log` show what recent runs hit. The shell is zsh: quote paths, and pass lists through `xargs`.
- **Agent prompts** (`/improve-agent-prompts`, and the `command-authoring` skill for new ones): naming and anatomy `.agents/rules/command-naming.md`; every apprentice-scoped command keeps its closing `## Step N: Self-update`. Regenerate a wrapper after a description change: `python3 -I .agents/skills/command-authoring/scripts/make_codex_wrapper.py <name> [<name> ...]`. Checks after editing prompts: `python3 -I .agents/skills/improve-agent-prompts/scripts/scan_agent_prompts.py` (0 errors) and `git status --short | grep '^ T'` (must print nothing). Weak-agent trials: `R=.agents/skills/improve-prompts/scripts/agent_runs/run_agent_trials.sh; bash $R snapshot; bash $R tasks; bash $R run <task>; bash $R show <run>` (free model only; never `--paid`). No planted tasks exist yet (`.agents/skills/improve-prompts/scripts/agent_runs/tasks/README.md`).
- **Prompts** (`/improve-prompts`): the app's own model prompt is the `run` loop's system prompt in `Sources/apprentice/AgentLoop.swift`; it has no tuning tool yet, so an experiment on it stops at Step 2 and asks. Agent prompts use the weak-agent trial harness in `.agents/skills/improve-prompts/scripts/agent_runs/README.md`, whose lab and experiment log live in `~/.agent_runs/apprentice/`. Trials must never run the `apprentice` binary, `kit.sh` or `install.sh`: they drive the real screen and install.
- **Session transcripts**: Claude Code `~/.claude/projects/-Users-robmllze-Desktop-apprentice/*.jsonl`; apprentice's own step logs `~/.apprentice/runs/<date>-<session>/steps.jsonl` and the scrubbed copies in `sessions/`.
